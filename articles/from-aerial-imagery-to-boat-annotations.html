From Aerial Imagery to Boat Annotations

By Erick Mulama Shituku

Examples of boats at different scales in aerial imagery. Green markers indicate mapped locations in one example; a marker is not itself a boat outline.

Start with images that can answer the question

Turning aerial images into useful map data takes more than spotting boats and drawing around them. It involves choosing images carefully, checking what can be seen, avoiding duplicate counts, and recording each mapped object consistently.

Before mapping begins, the images need to show the area and level of detail required. For small objects such as boats, resolution matters: there must be enough detail to distinguish a boat from surrounding water, shoreline, shadows, or other objects.

The image date matters too. Aerial imagery records what was visible when the image was taken. Boats may have moved since then, so an image cannot be treated as a current count of vessels. Record where each image came from and what its licence allows so others can understand and reuse the resulting data appropriately.

Check coverage before counting

A collection may contain many images, but some may show the same place. If a boat appears in two overlapping images, counting both sightings as separate boats inflates the total.

Compare each image’s footprint—the geographic area it covers—to find overlaps and possible duplicate sightings. When estimating visible boats, state how many images were reviewed, how they were selected, and how overlap was handled. A count from selected images is not a count of every boat in the wider area.

Separate image screening from object mapping

Large image collections can take time to inspect in detail. A screening step can help identify areas worth examining more closely. For example, a contributor might mark a small square if it contains one or more boats.

That mark answers, “Is there a boat somewhere in this square?” It does not say how many boats are present or show each boat’s shape and position. To create individual boat records, a mapper must inspect the relevant image more closely and draw a separate geometry around each visible boat. Screening locates possible objects; object-level annotations describe individual objects.

Draw and record annotations consistently

An annotation is a digital shape linked to a label, such as “boat.” Depending on the purpose and image quality, the shape may be a point, rectangle, or outline following the object’s edges. Choose one format and apply it consistently.

Each annotation should retain enough information to trace it back to its source image. Useful details include the image identifier, label, annotation method, and relevant date or contributor information. Without that link, it can be difficult to verify a feature or understand the conditions under which it was mapped.

Check the data before reporting a total

A file can contain records that look valid in a table but are unusable on a map. Geometries may be empty, misplaced, duplicated, or assigned the wrong label. Basic checks can identify these problems before the data is shared or analyzed.

A reported feature count should make clear what is being counted. The number of annotation records is not automatically the number of distinct boats: duplicates may remain, some boats may have been missed, and an annotation may not correspond to a verified vessel.

Quality checks can include reviewing a sample against the imagery, checking whether shapes align with boats, looking for duplicates, and recording corrections. Document the method and results so readers can judge the reliability of the data.

Make the result reusable

A useful geospatial dataset needs more than mapped shapes. Include source-image references, image dates, licences and attribution, coordinate system, annotation instructions, and known limitations. These details help others understand how the data was created, repeat the process, or decide whether it suits their needs.

From image selection to final checks, each step affects what the finished data can reliably say. Clear methods help distinguish a visible object, a mapped annotation, and a claim about the real world.
